# copilot-agents

Ploinky agent repository for explicitly deployed local Copilot provider agents and tested AchillesCLI-owned consumer integrations.

## Mandatory Reading Order

1. The workspace root `AGENTS.md` and any nested `AGENTS.md` for stricter local rules.
2. `docs/index.html` for the local documentation entry point and `docs/wiki.html` for canonical provider terminology.
3. `docs/specs/matrix.md` and the specific DS file(s) covering your change.
4. `docs/specs/DS002-ploinky-runtime-invariants.md` and `docs/specs/DS011-security-observability.md` before changing routing, manifests, MCP tools, file access, logs, or telemetry.
5. The sibling Ploinky and AssistOSExplorer specs referenced by the affected DS file when integration boundaries are involved.

## Repository Rules

- The DS specifications under `docs/specs/` are the source of truth for local contracts and invariants. Update them whenever code changes behavior, interfaces, or runtime configuration.
- Spec-code synchronization is an invariant: resolve disagreements against executable source, tests and the authorized product contract. Record supported rationale, limitations and unspecified integration boundaries declaratively in the affected DS Core Content; do not use a separate decision log.
- `AGENTS.md` is the single instruction file for every coding agent at this level; do not add a `CLAUDE.md`.
- Keep DS numbering contiguous within this repository. DS003 owns Main Behavior; DS015 owns the agent inventory. Ordinary DS files require exactly `title` and `summary` frontmatter, with the filename stem as title, and only `Introduction` and `Core Content` as top-level content sections. Do not add Conclusion or status/owner metadata. Preserve source paragraphs unwrapped and maintain the shared header, canonical wiki and documentation map together.
- Provider agents must not be added to AssistOSExplorer's default dependency list. They deploy only through the `research-agents` bundle.
- Provider backends are not direct chat launch targets. Authorized consumer tasks flow through `copilotProviderRelay` to the matching provider agent, which owns its local sandbox and execution policy. Generated-local Open Interpreter requests remain terminally refused before preparation. Optional typed launchers are distributed under `achilles-skills/`; RoboTeam does not include them in its bundled conversation skillset. Consumer selection and installation are separate integration requirements. The bundle must not enable a separate `basic/bwrap-runner` agent.
- The local manifest validator inventories only agent directories owned by this repository. AchillesCLI-owned consumers are checked through explicit sibling-repository compatibility roots, never by pretending their directories live here.
- Do not remove Open Interpreter privilege until native private-proc and real provider certification is recorded (DS006). Its runner image is already pinned by immutable digest after native publication proof; change that pin only with new native publication evidence. The retained privileged declaration is a transition allowance, not the target security posture.
- Code must follow the SOLID and DRY invariants in `docs/specs/DS001-coding-style.md`; use design patterns only when they clarify stable responsibilities or extension points.
- All technical documentation, specifications, and code comments must be in English.
- Never add Co-Authored-By, Generated by, or any other AI/coding-agent attribution to commits, documentation, code comments, release notes, changelogs, PR text, or other project records.

## Current Skill Catalog

The repository distributes three optional typed cskills under `achilles-skills/`: `launch-open-interpreter`, `launch-web-search` and `launch-browser-use`. Each owns its descriptor and executable module. They use the verified AgentMcpClient to probe provider status and submit tasks through the relay. Their presence does not install them into a sibling consumer or certify that consumer's runtime discovery. Provider agents expose MCP tools, not an imported instruction-skill catalog.

## Validation

Run the narrowest relevant check after edits:

- `node --test tests/unit/*.test.mjs` (GPTResearcher tests read the `legacy-agents` sibling checkout: set `LEGACY_AGENTS_ROOT`, default `../legacy-agents`; a missing checkout fails the tests, it never skips them)
- `node scripts/validate-manifests.mjs`
