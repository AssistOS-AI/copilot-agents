copilot-agents Documentation

The provider suite gives authorized Ploinky callers bounded execution tools, cacheable web search and persistent interactive browser sessions. An operator deploys the research-agents bundle explicitly. copilotProviderRelay validates each task and delegates it to a provider-owned runtime.

Source of Truth

The DS specifications under docs/specs/ are the source of truth for contracts and invariants. Code, configuration, and tests must follow them. Update specs in the same change as any behavior, interface, or runtime configuration change. Spec-code synchronization is a repository invariant, not an optional documentation task.

Quick Start

cd <workspace-root>
ploinky add repo copilot-agents <repo-url-or-local-path>
ploinky enable repo copilot-agents
ploinky enable agent copilot-agents/research-agents global
ploinky start research-agents

The bundle enables copilotProviderRelay, openInterpreterAgent, webSearchAgent, browserUseAgent, and GPTResearcher. GPTResearcher is supplied by the sibling AchillesCLI repository and is covered here as an explicit cross-repository shared-image compatibility surface. Backend availability is controlled by provider agents, not by direct backend chat agents, a separate bwrap-runner agent, or relay-owned command strings. webSearchAgent owns its local headless browser runtime and does not depend on an external search gateway.

Provider-private writable state is mounted from the workspace .data/<agent> root. Browser Use, Open Interpreter, and Web Search therefore persist beneath .data/browserUseAgent, .data/openInterpreterAgent, and .data/webSearchAgent while retaining /data inside each container. The manifest validator enforces this storage contract for root and profile-only volume declarations alike.

Agent Inventory and Compatibility Surfaces

  • research-agents - explicit deployment bundle
  • copilotProviderRelay - secure provider task relay
  • openInterpreterAgent - Open Interpreter provider agent
  • webSearchAgent - cacheable web-search provider with a local headless browser runtime
  • browserUseAgent - interactive browser provider with protected viewer for ChatGPT/Gemini login and OAuth flows
  • GPTResearcher - AchillesCLI-owned shared-runner consumer covered by cross-repository cold-install, readiness, and task contracts
  • launch-open-interpreter - optional consumer launcher for execution tasks
  • launch-web-search - optional consumer launcher for cacheable web search
  • launch-browser-use - optional consumer launcher for logged-in browser tasks

Provider task invocation

An authorized MCP consumer supplies a supported backend and prompt to copilot_provider_task_submit. The relay calls openInterpreterAgent, webSearchAgent or browserUseAgent through AgentMcpClient with the Router invocation token. It returns normalized output and applicable sources, state or viewer links. This repository distributes optional launch-open-interpreter, launch-web-search and launch-browser-use cskills under achilles-skills/. A consuming application must install and select compatible launchers explicitly. RoboTeam does not include those typed cskills in its bundled conversation skillset. Provider-looking @word text alone has no dispatch meaning.

Credentialed launcher and relay calls use Ploinky's verified AgentMcpClient, which validates the signed generated-local Router descriptor before credential or socket use. Generated-local Open Interpreter model execution returns terminal PLOINKY_OPEN_INTERPRETER_BOX_UNAVAILABLE before runtime preparation in this release; explicit operator-configured OPEN_INTERPRETER_* endpoints cannot override a Box descriptor and remain available only for separate non-Box local development.

Open Interpreter requires runner ABI 2 and private proc. Startup, readiness, status, and task admission use the canonical shared-runner contract, while outer runner stdout/stderr are retained only as bounded tails with discarded-byte counters. Its manifest and Python 3.12 cache select the immutable Trixie image sha256:9b6c08cf78fd0a29acfbe2e45ea2ee26efe6fde49c7f3db8b3aadfa30f2d53f8, verified on both native architectures by publication run 33662621018, while retaining its existing privileged compatibility declaration. This exact validator transition gate remains until native private-proc and provider certification permits privilege removal. Empty-proc success and private-proc unavailability do not certify Open Interpreter execution.

Specifications and checks

The specification matrix indexes provider requirements. DS001 owns coding style and modular tests. Deterministic provider checks live under tests/unit/; scripts/validate-manifests.mjs inventories local deployable agents. Cross-repository tests require their declared sibling checkout and do not establish a delivered RoboTeam launcher integration.
